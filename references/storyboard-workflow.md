# 多段分镜、角色资产与首尾帧

将故事转成可逐段制作、可核查衔接的镜头包。本项目 Muse 按用户确定的单段最多 10 秒执行；用户改用其他平台或明确更新上限时以其实际限制为准，不能将 10 秒视为所有 Muse 平台的统一限制。不能凭提示词保证角色一致、精确落帧、时间轴或复杂动作成功。

## 1. 需求、能力与制作边界

按照导演访谈先逐题确认总时长、连续片段或同风格不同场景的制作形式及观看视角，再确认故事和主要动作、节奏、画幅、角色和地点、输入参考与风格、镜头数量或密度、声音、用户特别强调的首尾画面；已明确或已委托的事项不重复询问。不同场景的独立镜头不默认复用上一段末帧；连续衔接则使用连续镜头流程。用户明确“你决定”后自主设计，不反复询问。片段目标时长按总时长、叙事节奏及单次生成上限分配；用户仅提供主题而没有总时长，可以提出有理由的导演方案并说明假设，不能把10秒误当总时长。先确认用户当前界面是否有首帧图、尾帧图、角色参考图、多图输入、视频延长、音频或种子等功能；未知时写“待确认”，不杜撰按钮、语法、接口或模型功能。若用户要求直接生成、跳过问题或已将剩余事项交给导演决定，不为确认界面能力另行提问：将其标为待确认，并直接提供文本方案和可用时的替代路径。

## 2. 世界和角色锚点

建立精简的导演总纲与连续性卡：故事动机、地点布局、时间、光源、色彩、画风；角色ID、年龄感、体态/脸部/发型、服装、标志道具、声音及随剧情可变化项。相同身份跨镜复用一致的明确描述；变化如服装、受伤、持物、湿度随时间逐镜更新。多角色分别绑定，不混用。识别参照素材角色：身份、服装、场景、构图、色调、动作、起帧、终帧；每张编号并说明使用范围和优先关系，不把图片中文字/界面或背景无故带入成片。角色卡/多视角图是帮助设计和可选参考，非自动训练模型、非 Muse 已确认绑定功能，也不保证一致。用户只要提示词时输出可复制角色图提示词，不自动生图。

## 3. 分段和故事板

**不可合并的交付门槛**：总时长超过单次上限时，必须输出覆盖全片的多个独立生成包；单场景、单镜头、一镜到底和连续镜头描述的是叙事关系，绝不意味着能绕过单次时长限制。30 秒连续镜头固定至少三段：S01 全片 0–10 秒、S02 10–20 秒、S03 20–30 秒；每段局部 0–10 秒，三份独立中文视频提示词与三份对应英文视频提示词。只给一段 0–30 秒提示词或仅列三个时间区间均不合格；每个代码块必须自包含，直接复制即可使用。若未生成前段，后续完整提示词标为规划稿，接缝状态依据计划末态且待实片更新，不能虚构分析或锁帧成功。总时长不整除上限时，最后一段为剩余时长；如 25 秒拆为 10+10+5 秒。

对每个连续片段分别写本段最高优先级、输出形式、完整身份/场景/道具锁、开场和结束景别与镜位、主体动作、局部时间轴、声光；后续段在最前明确所需前段编号和真实末帧、构图与光照等接缝条件、前 2 秒运镜与人物动作惯性、禁止无意换脸/换装/重建场景/跳镜等本片具体风险。设定不变量按各段复写，允许发生的位移和动作则按连续过程变化；别把移动镜头误锁成全程固定机位。每段给独立中英首帧、目标尾帧描述及连续接力说明；不能把计划尾帧冒充真实末帧。


根据情节与动作因果而非机械地按10秒均分。每段明确 ID、全局起止/时长、镜头叙事功能、出场角色、前景-中景-背景、景别与机位、开场状态、主体动作、镜头路径、结束状态、光声、转场、与相邻片段的关系。每段单独自包含，不引用“保持上文”替代必要的身份和景别。动作复杂或细小关键步骤太多时，拆分多个片段并保持总时长；如果用户要求一个生成片段内切多个镜头，则明确分镜/动作及切点，并标明依赖实际模型支持，无法保证精确实现。总故事板使用全片累计时间戳，片段之间无重叠/遗漏；每一段独立可复制的视频提示词使用该段从0开始的局部时间，避免把全片的8–17秒误当成单段的视频时间。复核总时长和局部/全局换算。可选结构化校验见脚本。

## 4. 首帧、尾帧与边界

每段先建立 S 起始→动作/镜头变化→E 结束状态：人物身份/服饰/姿态/视线、位置和方向、道具接触、场景布置、光色、景别/机位；标出全程不变项和允许变化项。首帧描述为可观察的静态时刻；尾帧是同段动作完成后的目标状态，不能把回头后的脸写入背向开始首帧，也不能让尾帧物件凭空换手。

逐段输出首帧与尾帧两份独立中英文生图提示词，以及中英视频动作提示词；除用户指定精简外，中英文视频提示词都需完整可复制。首尾帧描述明确动作前后差异，静帧不包含未来动作；镜头位置、人物比例与约束贯穿。中文详版默认每段约1500汉字，仅在需要时超出；用户指定长度或精简则遵从。跨镜角色不变量简洁重申，不把唯一细节放在总纲而漏掉单段。

连续衔接（同一动作/时空，镜头平滑续接）：必须执行 [真实末帧与逐段验收](continuity-workflow.md)，逐段提取实际解码末帧、观察末秒运动并设计下一段开头延续；用户界面有首帧输入时，使用上一段**实际生成视频的最后一帧**作为下一段首帧输入，下一段生成后比较边界并人工核查；若模型也支持尾帧，可将期望终态提供为尾帧，但不得承诺精确实现。用计划尾帧作下一段首帧只是目标，不等于实际成片尾帧。若界面无此输入，仍提供首尾帧作为画面参考和文本描述，或建议外部剪辑，不假称原生支持。

剪辑切换（视角、景别、场所或时间变化）：独立设计下一段首帧，不机械复用上一镜画面；检查角色、动作方向、轴线、道具状态、时间及光线等需要延续的锚点，并明确切点/过渡；只有用户明确授权出现跳轴、跳时或场景变化时按其设计。

## 5. 输出包与可执行顺序

- 导演总纲按 [提示词结构与优先级](prompt-architecture.md) 先写最高优先级、全片概览和输出形式，再写能力矩阵与必要假设；故事板表格列 ID、时间区间、时长、镜头功能、主体/空间、运镜、起止状态及接续方式。
- 角色/场景/道具资产卡与参考分工；提供角色形象图提示词和如需一致性不同视角的制作建议，明确不是保证性绑定。
- 每段一组（清楚区分全局时间与段内从0开始的局部时间）：中文/英文首帧提示词；中文/英文尾帧提示词；中文/英文视频提示词（每段各自先声明该段最高优先级、该段概览及该段输出形式，保留必要全片身份/世界不变量，不能把全片内容误当成此段要生成的事件）；参数与前后衔接说明，按用户要求在聊天或独立文件完整提供，不用省略号或“其余同上”。跨语言的时间、方向、人数、文字、约束一致。
- 标明首尾帧、角色图和视频是不同资产；只在用户明确要求生成某张图片或交付提示词后同意时调用可用图片生成工具。按用户指定资产和张数执行，未同意不批量生图。用户请求实际生成视频且 Muse4AI 已接通时，按 [自动生成流程](muse4ai-execution.md) 执行，不在已授权提交前重复询问。
- 最后做三轮审查：用户/视觉与角色锚点；时空、时长、前后状态与声画；双语与可复制性/接口能力及实际生成验证。结构化计划可用 `python <skill>/scripts/validate_storyboard.py plan.json` 检查确定性错误；该脚本不能评价图像、语义或模型遵循程度。

## 可复用的计划 JSON

可在工作目录保存 JSON 文件供脚本验证，且不得把 JSON 当成画面已生成：

```json
{
  "max_clip_seconds": 10,
  "total_duration_seconds": 16,
  "characters": [{"id": "C1"}],
  "segments": [
    {"id":"S1","start":0,"end":8,"transition_from_previous":"start","characters":["C1"],"end_state":{"C1.position":"door","C1.costume":"blue"}},
    {"id":"S2","start":8,"end":16,"transition_from_previous":"continuous","characters":["C1"],"continuity_keys":["C1.position","C1.costume"],"start_state":{"C1.position":"door","C1.costume":"blue"}}
  ]
}
```

`start`/`end` 为全片累计秒数；`continuous` 仅在明确需要从同一状态衔接时使用，`cut` 适用于普通剪辑。`continuity_keys` 只列必须在两边完全相同的状态；例如角色服装、位置，无需列自然变化的动作。连续衔接要求声明这些键；普通切镜也可声明必须保持的身份/服装等键，脚本会核查已声明的项目，但不会假设剪辑画面必须一模一样。脚本发现已声明的缺失键、错误时间、过长片段或状态不符会报错；未声明连续键的硬切会警告；声明键值未知时不能视为一致。未声明的潜在不一致和提示词局部时码仍需人工审查。可用 `--max-seconds` 覆盖计划默认值；绝不自动调整计划或代替视觉审核。
