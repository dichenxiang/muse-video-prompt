# Muse4AI 自动生成与逐段连续执行

本流程参考 [Muse4AI](https://github.com/andrew-babo/muse4ai) 的本地 MCP/REST 接口。它是独立第三方 Windows 桥接程序，并非 Muse 官方接口；实际能力、配额、接口版本和服务条款以用户环境为准。生成会使用用户的 Muse 额度。

## 触发、接入与边界

- 用户请求生成视频或在本次访谈中选择自动生成时：完成导演访谈、分镜、中英文提示词及三轮审查后，自动按已授权的段数调用 Muse4AI；不要再仅因提交任务重复询问是否生成。用户只要求提示词、明确不生成或暂停时不提交。用户明确要求图像/首帧时可以调用对应工具；单纯设计视频不自动生成额外首帧图片，除非工作流必需并获得用户授权。
- 优先发现并使用已连接的 `muse_status`、`muse_generate`、`muse_get_job` 等 MCP 工具；若没有，则在本机 Muse4AI REST 服务可用且安全配置了 `MUSE4AI_API_KEY` 时，使用 `<skill>/scripts/muse4ai_client.py`。连接前读取本机 `/v1/openapi.json` 或当前工具 schema，核对版本、参数和能力；若接口不同，不能虚构调用或把第三方行为当 Muse 官方承诺。
- 自动生成所需服务未安装/未启动、未登录、未配置 MCP 或缺少安全凭据时：先完成可交付的设计，明确哪个依赖阻塞实际生成；请用户在自己的 Windows 上安装并启动 Muse4AI、登录自己的 Muse 账号，并在应用设置中启用 API/MCP 和安全配置授权。OAuth 由用户自己完成，API key 只从受保护的配置或进程环境读取，不要求粘贴到聊天，不打印到命令、日志、提示词、仓库或回执。工具不具备凭据时不可声称已生成。
- 检查 `muse_status`：需要有就绪账户、所需视频/参考能力和可用额度；连续模式另核实接口是否有**明确首帧输入能力**。普通参考图或上传 endpoint 不能自动认定为严格首帧；用户若要求严格首帧但当前接口仅声明参考图，允许完成 S01，但实际发送 S02 前必须停止并说明需要支持首帧的接口，除非用户明确接受参考图近似方案。若已证实工具支持严格首帧，则把真实末帧送到对应字段，不伪造参数。

## 提交与状态

1. 在可写的项目工作目录为这次任务创建新目录，保存分镜总纲、逐段中英提示词、角色/道具/场景不变量及记录；不保存 API key 或带签名的下载链接。检查目标接口提示词限制；Muse4AI 所查版本的 `muse_generate` 提示词上限为 4000 UTF-16 代码单元，以当前 API schema/实际校验为准。提交一种用户选择或默认中文的视频提示词；中英完整导演稿仍分开保留。若过长，制作保留最高约束的提交版，明确说明并核对，不静默截断、拼接两种语言或丢失关键约束。
2. 给每次独立提交或延长动作建立唯一 ASCII request ID，先记入运行记录；同一次请求的网络不确定结果只用**原 ID 和完全相同内容**查询/重试，不能创建新 ID 或改变 payload 猜测性重复扣额度。一个已授权的多段计划按必要段数串行提交；不得自行增加额外候选数或无限循环。预算与重试上限以用户授权为准。
3. 发送后记录 job_id 并通过 `muse_get_job` 或 CLI `job ID --wait 30` 查询；`queued`/`running` 等待，`succeeded` 下载，`failed` 检查错误，`cancelled` 结束，`needs_review` 停止自动重发并请用户在应用中查看。`PRE_SUBMIT_TRANSIENT`/`PROXY_FAILED` 按服务说明并在原 ID 允许的安全范围内重试；`PROVIDER_ERROR` 最多稍后重试一次；其他不确定情况先停止，不要重复提交。记住取消可能仍消耗额度。
4. 取回 `outputs` 中的 asset_id 和视频到工作目录，使用当前任务产生的资产，不任意访问其他文件；下载 URL 可能过期，重新查询任务即可。CLI 下载使用本机认证的 `/v1/assets/{id}/content` 而不向其他主机发送凭据；记录路径、尺寸、时间、hash、任务 ID、用户授权、实际状态，必要时输出可点击视频文件链接。

## 严格连续镜头：基于实际成片设计下一段

执行 [真实末帧与连续镜头验收](continuity-workflow.md)，按 S01→S02→S03 串行，不批量预生成后续段：

1. 下载 S01，调用 `continuity_frames.py extract S01.mp4 --last S01-last.png` 提取真实解码末帧；同时抽取最后约一秒的连续帧/视频，**实际用可视工具观看**最后一秒和末帧。读出相机是否固定/推拉/跟移/升降、方向与相对速度趋势、构图、人物位置/姿态/外貌/发型/服饰、道具接触和光线环境。抽帧命令和图像元数据本身不具备视觉理解；不可凭文件名或计划稿声称观察。
2. 结合用户给定的情节与总时长，创造符合动作惯性的下一步：先承接方向、速度、视线、步伐和镜头路径约两秒，再渐进发展；如果前段静止则从静止自然发生，避免无缘由急停、跳转、瞬移和突然反向。将用户明确不变的人物外貌、服饰、数量、环境建筑、天气光照、摄像机和构图逐项写入本段提示词；末态等可变信息以真实画面更新。背景和道具不凭空换位置。
3. 在 S02 双语提示词开头写出真实末帧首帧约束、绑定范围、全局与局部时间、接缝人物位置、服饰、光线及镜头运动。若已确认严格首帧能力，则上传 S01 真实末帧并按实际 schema 作为首帧输入；普通 `reference_id` 只能表述为参考，不得假装首帧硬锁。S03 同样使用 S02 的真实末帧，逐段重新观察，不引用 S01 代替 S02。
4. 每段完成后，提取其第一帧与前段末帧，使用 `continuity_frames.py compare` 比较，并实际查看接缝前后动作和人物、构图、光线、道具。PSNR 只能提示画面差异，无法证明动作或身份连续，也不保证模型服从。质量不达要求时停止推进，指出具体差异；在用户已授权的重试上限内单项修订，若没有重试额度/授权则先提供结果与问题，不自动增加生成次数。镜头出现允许的运动时只锁接缝状态，不把全程画面强制静止。
5. 若 `muse.video.extend` 可用，可按用户意愿采用单次 `muse_extend_video` 或 CLI `extend ASSET --request-id ID --directive-file PATH`；每次仅一步，等待并分析返回结果再决定下一步。该项目通过 Muse 会话发送续接说明，输出可能为**包含前片的累计视频**；不得当独立片段重复拼接，也不能把会话续接等同严格首帧输入。验证输出长度、原片保留和实际接缝。严格首帧要求下，未经用户明确接受，不能以未核实的会话续接替代真实首帧绑定。

## REST 客户端：可执行示例

先在独立安全环境中设置 `MUSE4AI_API_KEY`；不要把密钥写入下面命令、提示词或可共享文件。CLI 固定连接 `http://127.0.0.1:47821`，不接受远程地址或重定向。非默认端口或 OAuth-only 用户优先使用配置好的 MCP；不要把密钥传给不可信的远程服务。下面的 `python` 路径应替换为已安装 skill 的绝对路径：

```text
python <skill>/scripts/muse4ai_client.py status
python <skill>/scripts/muse4ai_client.py submit --kind video --prompt-file S01-zh.txt --request-id project-S01-v1
python <skill>/scripts/muse4ai_client.py job JOB_ID --wait 30
python <skill>/scripts/muse4ai_client.py download ASSET_ID --out S01.mp4
python <skill>/scripts/continuity_frames.py extract S01.mp4 --last S01-last.png
python <skill>/scripts/muse4ai_client.py upload S01-last.png
```

上传只返回参考素材 ID，不证明能够严格控制首帧；将 `--reference-id` 用于普通参考时必须如实说明。接口的具体账户、额度、能力及生成效果依当前服务返回。脚本不会自动拼接、观看或判断视频；语义分析与导演决策由能实际读取媒体的 Codex 完成。
