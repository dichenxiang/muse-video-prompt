# 视频反推：逐帧证据到可复制提示词

## 1. 取得和检查视频

接收本地路径或可访问附件。用户提供链接时用可用、授权的工具取得可分析视频；遇到登录、下载限制或无法读取时说明原因并请求可访问文件，禁止编造画面。用 ffprobe 记录时长、分辨率、帧率、音轨；旋转与可变帧率须以实际解码及呈现时间戳为准。视频声音独立听取或由可用音频工具分析；无法收听、辨认或转写就标为未知，不凭画面猜配乐/对白。

## 2. 全帧扫描和视觉复核

优先执行本 skill 的 `scripts/analyze_video.py`，使用 Python 3、ffmpeg、ffprobe 和 Pillow；指定新的空输出目录，绝不覆盖输入或既有文件：

```text
python <skill绝对路径>/scripts/analyze_video.py <视频绝对路径> --out <新建或空的输出目录绝对路径>
```

脚本按呈现顺序解码并保存每一帧的缩略图、时间戳和带编号的分批联系表，写入 manifest.json。脚本是素材整理工具，不识别主体、镜头或动作。按顺序逐张查看所有联系表，对用户要求的全视频逐帧进行视觉分析；不要只打开其中几张便声称逐帧看过。联系表字小、动作快速或细节不确定时，按 manifest 找对应单帧查看；必要时按时间用 ffmpeg 抽原分辨率局部区间逐帧核对。时间以输出时间戳为准，注意可能非零起始、重复或缺失。

长视频帧数和联系表可能很大：先告知工作量并分段处理；能力、上下文、费用或时间不足以看完时，明确报告实际看过的帧号/时间范围、总量和未覆盖部分，继续在已覆盖范围内提供可靠结果，不把程序解码当作逐帧视觉理解。脚本缺失依赖、坏文件或时间戳与解码帧数不符时报告具体错误；可使用其他可靠手段，但必须说明覆盖情况。不要默认执行外部付费 API 或上传原片。

## 3. 建立带证据的镜头表

按实际切换划分镜头。对每镜头记录时间范围、主体与场景、起始→动作变化→结果、摄像机相对主体的运动、空间位置/接触、光线材质、风格、过渡，以及原声中可确认的内容。引用重要帧号和时间戳作为证据。镜头切换、运动模糊、遮挡、短闪、关键动作和文字出现处放大查看。区别镜头运动和主体运动，无法确定时写观察到的相对变化；不要将镜头焦距、布光方式、设备型号当成可直接观察事实。

## 4. 生成提示词包

先给简洁镜头拆解与关键证据，再给每镜头完整可复制提示词，包括主体、场景、构图、动作次序、运动、光线、风格、声音（仅有依据或用户要求）与连续性。多镜头加人物/服装/场景一致性设定；用户要求一个整体提示词时再合并。默认输出内容一致的中文和英文两份完整提示词；用户明确只要一种语言时遵从。可以提供与画面相近的可执行运镜方案，但须区分观察与创作建议。不可辨文字及对白标未知，不编造；相似并不等于恢复原提示词。

给出实际观察覆盖（逐帧数、时间范围、漏检帧、声音是否听取）和限制。证据表、提示词和清单应相互一致；如果存在未完成的视频片段或声音，明确列出。可以在输出目录保留 manifest 和联系表供核查。

## 5. 交付前逐稿审查

反推提示词草稿与证据表完成后，执行 [三轮逐稿审查](prompt-review.md)，每轮修订后再进行下一轮。重点核对观察、推断、时间范围、音频和用户要求的改动；未查看片段不得补写为事实。

## 6. 双语与首帧

按 [首帧与双语交付](first-frame-bilingual.md) 校对两个语言版本，用户要求实际生成视频时按 [Muse4AI 自动生成流程](muse4ai-execution.md) 提交；额外生成首帧图时按需询问；用户明确不提问或只要提示词时省略询问；未获得明确同意不调用图片生成。原片中不可见信息不因生成首帧而视为已知。
